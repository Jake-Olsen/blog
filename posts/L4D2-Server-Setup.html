This is a full fledged guide on how to Setup a Dedicated Game Server for Left 4 Dead 2.

I have been excited to finally release this guide as Left 4 Dead 2's Server has felt like the hardest struggle to overcome all the nuances, missing documentation, dead links, old legacy functionality that no longer works, and much more.

Setup Guide updated as of January 27th 2026

Requirements:

  • 2 CPU Cores
  • 2 GB of RAM Storage:
  • 10GB for the Game Server
  • 10GB for Debian 13
  • 20 GB for Mods + Flexibility in managing server.
  • Total of 40GB is recommended.

I'm running this in a Virtual Machine (VM), but an old computer will work fine as well. However do note that if you make a VM and clone it or clone the physical storage to make a 2nd server. There are extra steps needed, otherwise they will not properly be unique and you will run into conflict issues. If you are using a VM, then make sure to install the hypervisor's guest tools on the VM as then it is aware and can optimize things properly.

I'm not going to go over how to install Linux, dealing with clones, nor my full personal setup in this guide. However, you can find more information over in my other post: LINK TO JAKE TEMPLATE SERVERS

note I like to use vim/neovim(nvim) if you see nvim in the guide, feel free to use nano instead or whatever other text editor you prefer.

  1. Download and Install Debian. (You can use other Linux distros like Ubuntu, or whatever you are comfortable with)

    • Recommend to use UEFI, with GPT Disk, and LVM Partitioning as this will allow you to more easily adjust for more or less space as needed if you change the disk size later.
    • Recommended to just do the bare necessity tools and SSH server. A desktop environment is not needed and takes up processing power and memory for something you probably won't login to often after setup. Command line is the recommended way to go for most servers.

  2. create a 2nd user that will have restricted permissions and the game will run under that user for better security. Don't run the server as Root, don't run the server as your Admin user that has sudo privileges. In this example I named my user lefty, but you could name your steamuser for example.

Install SteamCMD

  1. You'll need to enable 32 bit packages for this old game & SteamCMD. 
sudo dpkg --add-architecture i386
  1. Make sure each Debian mirror lines includes contrib non-free non-free-firmware inside sources. 
sudo nvim /etc/apt/sources.list
  1. Update apt after the above 2 steps 
sudo apt update
  1. Download & install SteamCMD 
sudo apt install steamcmd

alternate method to download SteamCMD can be found on Valve's Wiki https://developer.valvesoftware.com/wiki/SteamCMD (manual section mentions curl and url link)

4a. optionally install rsync (file transfer tool) and ripgrep (search tool) 

sudo apt install rsync rg
  1. run SteamCMD at least once as the restricted user.

Note: SteamCMD is a bit different than other apps and may not be in your PATH. This usually will show you where it is at. 

which steamcmd

manually run SteamCMD at least once as your restricted game user (my example user is named lefty) 

sudo -u lefty /usr/games/steamcmd

you'll see output similar to:

Initial Test of the Server

First check the permissions, owner, group of the files to be sure they are correct before attempting the first test. (e.g. if you transferred the files as your admin user, not as restricted user, they'll belong to the wrong owner user)

These 2 commands should fix common permission & owner issues 

sudo chown -R lefty:lefty /home/lefty/
sudo find /home/lefty/ -type d -exec chmod 770 {} +

to login as lefty with bash shell run this: 

sudo -u lefty /bin/bash
cd ~

Here is the command to run the game 

/home/lefty/l4d2server/srcds_run -console -game left4dead2 +maxplayers 4 +ip 192.168.1.67 -port 27015 +exec server.cfg -norestart

If you need to close it type quit

I wouldn't recommend using Ctrl + C to cancel it as it leaves the terminal in a weird state, requiring to log out and log back in to fix it.

Do note that the server binary wants hypen - and plus + for different parameters and doesn't match documentation. Through old posts on steam community , reddit, and forums. Along with trial and error. I eventually got the errors to go away.

IP needs to be + plus

  • e.g. +ip 192.168.1.69 Port needs to be - hyphen
  • e.g. -port 27015 server.cfg file needs to be inside cfg folder. The default server.cfg file in the main directory is not read by the server.
  • e.g. ~/l4d2server/left4dead2/cfg/server.cfg

Security and Firewall

I'm going to use and recommend UFW Uncomplicated Firewall

First you need to allow SSH so you can access the server. (Don't Expose SSH to the Internet, you can access locally, or use Tailscale/VPN to access while not home) 

sudo ufw allow OpenSSH comment 'Allow SSH'
sudo ufw reload
sudo ufw enable

create the application profiles for easier management (optional) 

sudo nvim /etc/ufw/applications.d/ufw-jake-l4d2
sudo nvim /etc/ufw/applications.d/ufw-jake-steampowered

Examples: 

root@deb13temp:~# cat /etc/ufw/applications.d/ufw-jake-l4d2
[Left4Dead2]
title=Left4Dead2
description=Left 4 Dead 2 Dedicated Game Server
ports=27015:27020/udp

root@deb13temp:~# cat /etc/ufw/applications.d/ufw-jake-steampowered
[Steam_Game_Services]
title=Steam_Game_Services
description=Steam_Game_Services
ports=27015:27020/udp

sudo ufw allow Steam_Game_Services comment 'Steam_Game_Services'
sudo ufw allow in proto udp to 0.0.0.0/0 app Left4Dead2 comment 'L4D2_Game_Server(IPv4_Only)'
sudo ufw reload
sudo ufw status verbose

Note: The reason for IPv4 only rules is because Left 4 Dead 2 only supports IPv4 only. Surprisingly it doesn't even properly support DNS A Records. For example I can't connect via l4d2.mydomain.com:27015

Now that the firewall has been setup and ports are opened you should be able to connect in game. This is the command you have to run inside game's dev console. 

mm_dedicated_force_servers Public_IP_Address:PublicPort:Private_LAN_IP_Address:PrivatePort

e.g. 

mm_dedicated_force_servers 123.456.789.123:27015:192.168.1.67:27015

Security Part 2

Lets lock down SSH even more. 

nvim /etc/ssh/sshd_config.d/01-jake-server.conf
nvim /etc/ssh/sshd_config.d/02-game-server.conf

root@deb13temp:~# cat /etc/ssh/sshd_config.d/01-jake-server.conf
AllowUsers jake
PasswordAuthentication no
PermitRootLogin no
root@deb13temp:~# cat /etc/ssh/sshd_config.d/02-game-server.conf
AllowUsers friend1,friend2
DenyUsers lefty

Prevent anyone from directly logging in as our restricted game user. 

usermod -s /usr/sbin/nologin lefty

Again I would recommend NOT opening SSH to the public internet. I also wouldn't recommend installing a VPN nor Tailscale directly on the game server. This is because it can cause issues with the game server.

Here are some potential solutions if you want or need to give access remotely.

  1. Install Tailscale on another machine and on the remote machine. (Highly Recommended) This option is very easy to setup and doesn't require opening ports on the router firewall.
  2. With an Allow List on the router firewall, you can open the SSH Port into a Server. This would mean you need the public IP of the remote network.
  3. Setup SSH on another machine, then use it as a Jump Host/Bastion to access the server.

.ssh/config example 

Host myJumpHost
    HostName 123.456.789.123
    User jake
    ProxyJump myJumpHost
    IdentityFile ~/.ssh/yourPrivateKeyPathHere
Host l4d2
    HostName 192.168.1.67
    User jake
    IdentityFile ~/.ssh/yourPrivateKeyPathHere

You can combine this with option 1 or 2 to get remote ssh access. It looks like this: Remote Computer ➡️ myJumpHost ➡️ l4d2 Server. I would recommend using SSH Keys over passwords. Also with the jumpHost machine option the private ssh key only has to exist on the remote machine. Don't put the private key on either the jumphost nor l4d2 server.

4th option, Install a VPN on another machine and give a route so it can get to the L4D2 Server. (Least Recommended, its complicated to setup, and you need to keep VPN server and software updated regularly)

Running the server long term

Option 1: Is to use tmux, screen, or byobu(tmux) to just keep the session open and you just re-attach it to it to start, stop, run commands on it, ect. Which can be useful for troubleshooting mods, ect.

Option 2: However running this as a SystemD service allows you to just start, restart, stop it and it just runs in the background. You can even 'enable' it to run on startup so that as soon as your boot it auto starts the L4D2 Game Server Service. Useful if the power goes out long enough, can just boot back up and it will come online if enabled.

I'm going with Option 2, a SystemD service. In this service it is configured so that logs are changed from console output to journal instead.

  • Tail logs to see them in real time: journalctl -fu l4d2.service
  • View older logs: journalctl -u l4d2.service --since "1 day ago" | grep Tank

L4D2 SystemD Service File Path Location: 

/etc/systemd/system/l4d2.service

L4D2 SystemD Service File Contents: 

[Unit]
Description=Left 4 Dead 2 Dedicated Game Server
Wants=network.target
After=syslog.target network-online.target

[Service]
Type=idle
Environment=LD_LIBRARY_PATH=/home/lefty/l4d2server
User=lefty
Group=lefty
WorkingDirectory=/home/lefty/l4d2server
RuntimeDirectory=lefty
StateDirectory=lefty
LogsDirectory=lefty

###Notes:
###IP needs to be +   ###
###Port needs to be - ###
###server.cfg file needs to be inside cfg folder ###
###e.g.  ~/l4d2server/left4dead2/cfg/server.cfg  ###
ExecStart=/home/lefty/l4d2server/srcds_run -console -game left4dead2 +maxplayers 4 +ip 192.168.1.67 -port 27015 +exec server.cfg -norestart

# Hardening for lockdown: restrict the service process to only necessary access
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=read-only
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
RestrictNamespaces=true
RestrictRealtime=true
SystemCallFilter=@system-service
ReadWritePaths=/home/lefty/l4d2server

#Logs are changed from console output to journal instead.
# - Tail logs to see them in real time: journalctl -fu l4d2.service
# - View older looks: journalctl -u l4d2.service --since "1 day ago" | grep Tank
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target

After creating this or if you make any changes to the file above. Always run a daemon reload afterwards: 

sudo systemctl daemon-reload

Now you can run the service.

  • Start, Stop, Restart are pretty self explanatory
  • Status will show if its running, and recent logs.
  • Enable will have the system automatically start the service after booting.

Here are some examples: 

sudo systemctl start l4d2.service
sudo systemctl status l4d2.service
sudo systemctl enable l4d2.service
sudo systemctl stop l4d2.service
sudo systemctl restart l4d2.service

Server Plugins and Mods

SourceMod (SM) is a very popular plugin system for loading server-side mods called plugins. SourceMod depends on MetaMod being installed.

So lets install both of them. Go to the websites and grab the latest builds https://www.metamodsource.net/downloads.php?branch=stable https://www.sourcemod.net/downloads.php?branch=stable

unzip them to the proper server location

tar xvf mmsource-1.12.0-git1219-linux.tar.gz --directory=/home/lefty/l4d2server/left4dead2/

One thing to note in the above is you can deny and allow similar commands separately, but can't specify parameters. For example I "allow a vote to slay ", but "deny slay". This thankfully does work. It allows a vote to be held, if the vote succeeds it slays the thing voted for. However you now can't directly slay without holding a vote, which is what I prefer.

For parameters, afaik those cannot be specified in the permissions config. For example: I can't specifically deny "sm_voteslay tank" to prevent admins from voting to slay the ai monster Tank game enemy. Therefore it's either allow vote for slay or don't allow at all. I don't want to restrict it too much, so the permission will stay. Admins can vote slay, including the Tank enemy.

// Maximum: "1.000000"
whitelist_tidykick "0"

To explain a bit how this works. Auto vouch = 1 means that if there is a player not on the allow list, it will only allow them to join if someone else on the allow list is already in-game.

Example 1: I'm in the game, and I make a friends only lobby, any of my friends can join. Even if I haven't added them to the server allow-list. However if I lose connection and I'm the only one there, it will kick them after a short period.

Example 2: I'm in the game with another friend on the allow list. I lose connection the game will continue on with player 3 & player 4. I can rejoin the match if the slot is still open.

Example 3: I'm in the game, I create a public lobby, 1 friend on the allow list joins. 2 more random people join. I lose connection, the game will continue, another random public player joins. I won't be able to join as 4/4 slots are full. It won't auto kick them.

Example 4: If someone tries to start a game on my server and nobody is on the list it will reject them. It keeps the server reserved for myself and my friends so we can play whenever we want to.

Note: SteamGroup and TidyKick require addition plugins and setup, that I have not looked that far into. They aren't necessary for my small setup.
